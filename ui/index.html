Step 1 of 3

Choose what to test

Pick the protections to test and how much to run. The defaults suit a first run.

Guardrails: the protections to test

A guardrail is a safety layer around the chatbot. Each test runs once per guardrail you tick, so they can be compared. If unsure, tick all.

The test chatbot cannot be reached. Runs will be refused until it is started.

Test size: how much to run

Start with Smoke to confirm the connection works. Use Standard for results you intend to report.

Advanced: documents, and testing another chatbot
Documents: what the chatbot reads from

The chatbot looks up documents before it answers. A poisoned document hides instructions or a link to an unknown website. You can change this at any time without restarting.

Single tools use the clean documents unless Poisoned only is selected.

Chatbot to test

The built-in test chatbot, or another chatbot reached by its address. It must accept OpenAI-style chat requests.

That chatbot receives every attack prompt. Use fake data only, and check your organisation's rules first. Enter the name of the environment variable that holds its key, never the key itself.

The variable must be set in the terminal where python target/server.py runs.

The fake secret placed in that chatbot. It is how a leak is detected, whatever any tool says.

If known, so that a long verbatim repeat of it counts as a leak.

Connected. Tick the guardrail named "External chatbot (relay)" above. It is tested on clean documents only.

Step 2 of 3

Run the tests

A guided scan picks the tools for you. Tick the risks to test, check the plan, and start.

How would you like to run the tests?

Guided scan

You choose what to test. The tools are chosen automatically, and the results appear as a table of risk against guardrail, with example replies. Saved to results/scans/<name>.md.

What should be tested?

The ten OWASP LLM Top 10 risks. Each card names the tools that test it; dashed labels are slow tools. Greyed-out risks have no automated test yet.

Options: slow tools and scan name

Letters, digits, hyphens and underscores only, up to 40 characters. If left empty, a name is generated from the date and time.
