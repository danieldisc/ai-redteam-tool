Settings

Choose these settings once. They apply to both ways of running and to every job in the Queue.

Chatbot to test

Test the built-in test chatbot, or another chatbot reached by its address. The other chatbot must accept OpenAI-style chat requests.

That chatbot receives every attack prompt. Use fake data only, and check your organisation's rules first. Enter the name of the environment variable that holds its key, never the key itself.

The variable must be set in the terminal where python target/server.py runs.

The fake secret placed in that chatbot. It is how a leak is detected, whatever any tool says.

If known, so that a long verbatim repeat of it counts as a leak.

Connected. Tick the guardrail named "External chatbot (relay)" below. It is tested on clean documents only.
Guardrails: the protections to test

A guardrail is a safety layer around the chatbot. Select one or more. Each test is run once for every guardrail selected, which allows them to be compared. If unsure, select all.

The grey code on each card is the name used in the Queue and in the results.

The test chatbot cannot be reached. Runs will be refused until it is started.

Test size: how much to run

Use Smoke first to confirm that the connection works. Use Standard for results intended for reporting.

Documents: what the chatbot reads from

The chatbot looks up documents before it answers. A poisoned document contains hidden instructions or a link to an unknown website. This setting can be changed at any time without restarting.

Single tools use the clean documents unless Poisoned only is selected.
